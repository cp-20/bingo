# 会場の役割から見直したレビュー

想定は忘年会100人、司会1人・景品係2人・投影用PC。参加者は片手のスマホ、司会は客席を向き、景品係は受け取りに来た人を確認する。300人・同着多数・長い題名と名前も別のブラウザ検査で扱う。

## 進行と情報の主役

| 場面       | 司会                               | 参加者                                 | 投影を見る人                  | 景品係                         |
| ---------- | ---------------------------------- | -------------------------------------- | ----------------------------- | ------------------------------ |
| 受付       | QRと参加数を確認、景品を写真で紹介 | カードを受け取り、景品を見る、チャット | 入り方と「何が当たるか」      | 専用リンクを開き、現物を準備   |
| 抽選       | 次の番号、スクリーン用表示を確認   | 自動で開くカード、リーチに必要な番号   | 大きな番号、景品、リーチ人数  | 待機                           |
| ビンゴ     | 同着を確認、景品を決める           | 喜ぶ、拍手を送る、案内を待つ           | 大きな名前とBINGO、同着の扱い | 当選確定を待つ                 |
| 景品確定   | 当選者紹介、次の抽選へ             | 自分だけの受け取り番号を確認           | 名前と当たった景品の写真      | 6桁を照合、成功表示後に手渡す  |
| 次のゲーム | 結果を保存して再開                 | 同じカードで再参加                     | 受付へ戻る                    | 前ゲームの受け渡し待ちも続ける |

「紹介中」と「獲得」を区別する。番号一覧を常時主役にはしない。司会が必要なときに切り替え、次の抽選で戻る。チャットは参加者同士で読み、投影は司会の選んだ投稿だけ。音は投影用PCで明示的に有効にしたときだけ鳴る。

## 敵対的レビューで見つけ、修正したもの

| 具体的な失敗                                         | 修正と根拠となる検査                                                           |
| ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| 二人の景品係が同時に同じ景品を渡す                   | 受け渡し状態をトランザクション内で照合。同時確定は1件だけ成功する単体テスト    |
| 古い幹事画面で解除し、新しく選ばれた別人の景品を消す | 表示していた割当IDを照合するテスト                                             |
| 次ゲームで同じ現物がもう一度配られる                 | 当選者と受け渡し記録を維持。前ゲームの受取証・待機一覧が残るテスト             |
| 受け渡しの成功行が消え、渡してよいか分からない       | 相手と景品を含む成功表示を一覧の上に残す通し操作テスト                         |
| チャットに気を取られてビンゴや当選に気づかない       | チャット内の番号・成立・景品案内を更新。入力とカーソル位置を保持する通しテスト |
| 景品を確定後に終了しても特定の当選者紹介が残る       | 終了操作で明示ステージを解除するテスト                                         |
| 自由投稿が突然スクリーンに出る                       | 公開投影用の取得では選択済み投稿だけを返す。選択前は映らない通しテスト         |
| 固定投稿が新しい60投稿に押し出される                 | 最新の会話と選択投稿を別条件で取得。70投稿後も残るテスト                       |
| 再送でチャットや拍手が増える                         | 投稿IDによる再試行、番号ごと1人1リアクション、投稿間隔制限のテスト             |
| 写真が横向き、位置情報が残る、変更失敗で元が消える   | 回転補正後にJPEGへ再生成。画像の向き・メタデータ除去・失敗時の維持を検査       |
| 受け取り番号を他人が見る                             | 本人だけに受取証を返す。投影・他参加者・景品係の一覧にコードが含まれないテスト |
| 長い名前の同着、低い画面で主操作が切れる             | 1280×720/800/1080、スマホ320/390で描画と領域を検査                             |

単体テストに加え、幹事・参加者・投影・景品係の4画面を本番ビルドで操作する。写真の登録→紹介→チャット→選択投影→リーチ→チャット中のビンゴ→景品割当→誤った6桁→正しい受け渡し→次ゲームまで確認する。通常の復帰・オフライン・全75番号・動きを減らす設定も維持する。ChromiumとWebKitはCIで実行する。

## 確認範囲

ローカルの300人同期API負荷確認は、参加者300人の資格情報を順番に使い、ホストの抽選中に620リクエストを送るもの。外部DB、ロリポップの実プラン、会場回線の容量保証ではない。実会場の投影距離・照明・音量、iOS/Android実機、スクリーンリーダーの手動確認は未実施。

Sitesは同じブラウザ内の操作デモで、実端末同士のイベント・本決済には使わない。写真3点は架空の景品を示す生成画像で、実際の商品や提供を示さない。Stripeはsandbox専用を維持する。
