# BINGO ROOM

幹事向けのイベント用ビンゴWebアプリ。無料30人、有料プランは **1イベント2,980円（税込）・最大300人**。

**現バージョンはStripe sandbox専用です。実際の課金・本販売には対応していません。** liveキー・liveイベントは拒否します。月10万円の利益は事業目標であり、保証されるものではありません。

## 使える機能

- ニックネームとQR/8文字コードで参加。参加者の会員登録・アプリは不要
- 幹事、会場スクリーン、参加者カード、権限を絞った景品係の4画面
- サーバーによる重複なし抽選、カードの自動反映、リーチ・ビンゴ・同着判定
- 30人/300人の人数上限をDBトランザクション内で制限
- 写真付き景品登録・スクリーンへの紹介・当選者への割り当て・本人の受け取り番号・受け渡し確認
- 参加者チャット・司会が選んだ投稿の投影・番号ごとの拍手や応援
- 場面に応じた投影、ビンゴの当選者紹介、任意の効果音、動きを減らす設定
- 結果CSV・参加済みカードの印刷
- 幹事用リンク・参加者本人用の復帰リンクで別端末から再開。通信切断時の再試行でカードを増やさない
- sandbox Checkout、署名検証付きWebhook、金額/通貨/イベント照合、重複通知の排除、非同期決済と失敗後の再試行

## ローカル起動

Node.js 22.12以上（24推奨）。

```sh
npm ci
cp .env.example .env.local
npm run dev
```

http://localhost:3000 を開きます。開発用DBは `data/bingo.db` に自動作成します。`APP_URL` とブラウザで開くURLのoriginを一致させてください。localhostと127.0.0.1は別originです。

```sh
npm run typecheck
npm test
npm run build
```

ビルド後は `npm start` でstandaloneサーバーを起動できます。HTTP経由の確認は、開発サーバーを起動した状態で `npm run test:http` を実行します。`.githooks/pre-commit` はキーの混入を検知するフックです（利用時は `git config core.hooksPath .githooks`、`rg` が必要）。

テストはローカルの一時DBを使います。決済はスタブで検証し、Stripeへリクエストを送りません。ブラウザテストはビルド後に実行できます。

```sh
npx playwright install --with-deps chromium webkit
npm run build
npm run test:e2e
BINGO_TEST_BROWSER=webkit npm run test:e2e
```

Playwrightはループバックに限定した独立サーバーと一時DBを使います。`BINGO_E2E` はテスト用であり、公開ホストには設定しないでください。

## 構成

Next.js App Router / React / TypeScript / libSQL / Stripe Checkout。`output: 'standalone'` でロリポップ！デプロイナウに対応します。DBの書き込みはトランザクションで行い、ゲーム番号と抽選回数の照合で二重押しや前のゲームの操作を防ぎます。カード・抽選・有料権限の正本はサーバーです。DBスキーマはバージョン管理し、既存イベントを保ったまま移行します。

ゲームとチャットを1つの同期APIで取得します。通常、参加者は3.5〜3.75秒、幹事は1.8〜2.05秒、投影は1〜1.25秒間隔で参照します。同じブラウザの別タブへは、秘密情報を含まない変更通知でも再確認します。部屋ごとの読み出しを500ms・最大200部屋で共有し、同時の読み出しを1つのSQLにまとめます。自身のプロセスで書き込むと即座に無効化し、別プロセスの変更もキャッシュ更新時に読み直します（有効期間500ms。画面の反映にはポーリング間隔も加わります）。参加者には自分のカードに必要な情報を返します。ゲームとチャットは別の更新番号で管理し、投稿ごとのカード再送を避けます。どちらも変化がない場合は204を返し、切断時は待ち時間を延ばして再接続します。古い応答で新しい状態を上書きせず、同期できていない間は幹事の操作を停止します。WebSocket対応が公式に明記されていないホスティングでも動作する構成にしています。

書き込み待ちは各プロセス128件・8秒を上限とし、超過時は再試行可能な503を返します。外部DB通信は8秒でタイムアウトし、Next.jsのfetchキャッシュを無効にします。

本番でファイルDBを指定したり、外部DBを未設定にしたりすると、イベント操作は503で停止します。再デプロイでカードや購入済みイベントを消さないためです。トップページと使い方は閲覧できます。

## デプロイ

詳細は [docs/DEPLOY.md](docs/DEPLOY.md)。外部libSQL/Turso DB、公開URL、必要に応じてsandboxキーとWebhook署名シークレットを、デプロイ先の環境変数へ設定します。秘密情報はGitHub・チャット・コマンド履歴に保存しないでください。

```sh
npx lolipop login
npx lolipop deploy --name bingo-room --framework next
```

CIはGitHub Actionsで型チェック・単体テスト・本番ビルド・Chromium/WebKitの画面テストとアクセシビリティ検査を実行します。ロリポップのGitHub Appを接続するとmainの更新で自動デプロイできます。

運用と復旧は [docs/OPERATIONS.md](docs/OPERATIONS.md)、敵対的レビューと公開判定は [docs/REVIEW.md](docs/REVIEW.md) を参照してください。`/api/health` はプロセスの生存、`/api/ready` はDBとスキーマを含む利用可能性を確認します。

## 運用上の制約

- 最初の抽選から新規参加は停止。元のカードには途中でも復帰できます。
- 同じ抽選回でのビンゴは同順位。景品の割り当ては幹事が決定します。次のゲームへ進んでも景品の当選者・受け渡し記録は維持します。
- 写真はJPEG/PNG/WebPを受け付け、サーバーで回転補正・縮小・再圧縮してメタデータを除去します。チャットは140文字、参加者ごとに10秒で3投稿まで。
- 認証情報と復帰リンクを両方失った場合の本人確認復旧、景品の発送は対象外です。本人用のリンクは参加者間で共有しないでください。
- 印刷した紙は非常時の手動運営用です。完全オフライン抽選や紙で進めた結果の自動同期はありません。
- 無料イベントは7日、アップグレード後は決済確認から30日。期限から30日経過したイベントは、別途定期実行する `npm run db:cleanup` で削除されます。決済記録は保持します。
- 匿名作成はIP由来の時間帯別キーで10件/時、サービス全体で100件/時まで。IPヘッダーへの信頼は公開先のプロキシ設定に依存します。開催中のイベントは作成枠の消費後も継続できます。
- 300人の実際の会場・本番環境での負荷試験は別途必要です。CIは人数制限とローカル並行読み出しを検証します。
- 収益化にはsandboxでの実決済テストに加え、販売者情報・返金条件・live決済の別途準備が必要です。
